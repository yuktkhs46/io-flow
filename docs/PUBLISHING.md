# 公開と運用の方針（提案）

## 1. 全体の考え方

このツールは「年に数回しか変わらない公的統計」を「静的なページ」で見せるものです。サーバやデータベースは不要で、次の3層に分けて管理します。

| 層 | 中身 | 管理方法 |
|---|---|---|
| 元データ | e-Stat の Excel | リポジトリには入れない。`data/sources.json` に統計表IDを列挙し、`fetch.py` でいつでも取り直せるようにする。取得したファイルの SHA-256 を `data/raw/manifest.lock.json` に記録 |
| 加工データ | `data/processed/io.json` | リポジトリに入れる。数値の変化が Git の差分として残り、公開サイトのビルドが e-Stat の稼働状況に左右されない |
| 画面 | `web/`（HTML・CSS・JS）、`vendor/`（D3） | リポジトリに入れる。ライブラリも同梱し、外部CDNに依存しない |

## 2. 公開先：GitHub Pages を推奨

- 費用：無料（公開リポジトリの場合。非公開リポジトリは有料プランが必要）
- 仕組み：`main` に push すると `.github/workflows/deploy.yml` がページを生成して公開
- 独自ドメイン：設定画面から追加でき、HTTPS も自動
- 代替：Cloudflare Pages（非公開リポジトリでも無料、アクセス解析付き）。構成はほぼそのまま移せます

公開までの手順:
1. GitHub にリポジトリを作り、このフォルダを push
2. リポジトリの Settings → Pages → Source を「GitHub Actions」に設定
3. Actions タブで「Deploy site」が成功すれば `https://<ユーザー名>.github.io/<リポジトリ名>/` で公開されます

## 3. データ更新の流れ

e-Stat の表は公開後も正誤情報で差し替えられることがあります（2020年表も 2025-07-11 に更新されています）。

- **自動チェック**：`.github/workflows/update-data.yml` が毎月3日に全ファイルを取り直し、内容が変わっていればプルリクエストを作ります。解析時に行・列バランスと公式逆行列表との照合を行うため、表の形式が変わった場合はジョブが失敗して気づけます
- **人が確認してマージ**：`manifest.lock.json` の差分で変わったファイルを、`io.json` の差分で数値の変化を確認します。マージすると自動で公開サイトに反映されます
- **新しい表の追加**：`data/sources.json` に統計表ID・年・シート名を1件追記するだけです（下記）

データが増えて1ファイル（現在約0.5MB）が重くなったら、`io.json` を「部門分類×年」ごとに分割し、必要なときに読み込む形にします。

## 5. 公開前に決めておくこと

- **出典表示**：e-Stat のデータは「政府標準利用規約（第2.0版）」に従い、出典の明記と、加工した場合はその旨の記載が必要です。ページのフッターに「〜をもとに加工して作成」と記載済みです
- **ソースコードのライセンス**：公開リポジトリにする場合は MIT など何らかのライセンスを付けるかどうか
- **アクセス解析**：必要なら Cloudflare Web Analytics など Cookie を使わないものを推奨
- **免責**：「本ページの数値は公表値を加工したもので、公式統計そのものではありません」程度の一文をフッターに足すか

## 6. 品質チェック

| 何を | どこで |
|---|---|
| 行バランス・列バランス（各年・各部門分類） | `build_data.py`（失敗すると停止） |
| 逆行列が公式表と一致するか（2020年） | `build_data.py` |
| e-Stat 側の差し替え | `update-data.yml`（毎月） |
| 画面の表示 | プルリクエストの段階で `dist/io-flow.html` を開いて確認 |
